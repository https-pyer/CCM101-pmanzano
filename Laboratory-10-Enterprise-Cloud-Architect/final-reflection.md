## 🚀 3. Experience and Insights from Mission 10

Mission 10 was one of the most challenging activities because it required me to combine different technologies and apply them in a single working environment. Unlike activities that focused on individual configurations, this mission involved planning and understanding how multiple components interact with one another.

### 🐳 Docker and Docker Compose

One of the important lessons I gained was understanding how Docker and Docker Compose simplify application deployment and management. Docker allows applications to run inside containers with their required dependencies, making the environment more organized and consistent.

Through Docker Compose, I learned how multiple services can be defined and managed using a single configuration file. Connecting the application and database containers also helped me understand how different services communicate and depend on one another to make an application function properly.

### 💾 Persistent Volumes and Data Storage

Another important concept I learned was the use of persistent volumes. I understood that storing important information directly inside a container is not always reliable because containers can be removed, recreated, or restarted.

Persistent volumes provide a way to preserve important data even when changes are made to containers. This is especially important for databases because losing stored information can affect the entire application. This activity helped me appreciate the importance of proper data storage and protection when managing containerized systems.

### 🔐 Server Security and UFW Configuration

Security was also an important part of Mission 10. Through configuring UFW (Uncomplicated Firewall), I gained a better understanding of how administrators manage incoming network connections and control access to a server.

Applying a default-deny incoming policy and allowing only the necessary ports helped me understand why limiting network access is important. It reduces unnecessary exposure and provides an additional layer of protection against unauthorized connections.

This experience taught me that security should always be considered when designing and deploying an infrastructure rather than treating it as something that can be added later.

### ⚙️ Bash Scripting and Cron Automation

Another valuable experience was learning how to automate tasks using Bash scripting and Cron. I learned that repetitive administrative activities do not always need to be performed manually because they can be handled through scripts and scheduled processes.

For example, creating a backup script and scheduling it through Cron demonstrated how important tasks can automatically run at a specific time. This approach can help administrators perform regular backups, manage system files, and maintain their servers more efficiently.

Through this activity, I realized that automation helps reduce manual effort, saves time, and makes system maintenance more consistent.

### 📚 Technical Documentation and Project Organization

Lastly, I learned the importance of preparing complete and understandable technical documentation. Creating a README, architecture diagram, operational manual, and organizing the necessary project files helped me understand that documentation is an essential part of infrastructure development.

A properly documented project allows other users or administrators to understand how the system works, how it was configured, and what steps are needed to deploy or maintain it. It also makes troubleshooting easier and provides a useful reference when future modifications or improvements are required.

## 🛠️ 4. Challenges Encountered and Lessons Learned

Throughout the final mission, I realized that working with multiple technologies in one environment can be challenging, especially when different services depend on one another. A small configuration error in networking, container settings, storage permissions, database connections, or firewall rules can affect the entire application.

This experience taught me the importance of troubleshooting and checking each component carefully. Instead of immediately changing several configurations, I learned to approach problems systematically by identifying the possible cause, checking the service status, reviewing configuration files, examining error logs, and testing possible solutions.

I also learned that a container showing a running status does not automatically mean that the application is fully functional. The services must still be tested to ensure that they communicate correctly and that the application can access the required resources.

Another important lesson was the value of preparation and proper planning. Security, storage, and backup configurations should be considered before deployment because they play an important role in keeping the system reliable and protected.

Although some parts of the activity required additional time and effort, these challenges helped me become more patient and develop a better approach to solving technical problems. I realized that encountering errors is part of the learning process, especially when working with unfamiliar tools and technologies.
